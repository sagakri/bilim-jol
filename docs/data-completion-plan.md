# План заполнения данных JolTap для BilimJol

Дата проверки: 19.10.2026. Источники: локальная база `JolTap`, документ `JolTap_online.docx` от 16.10.2026 и официальные страницы, указанные ниже. Первоначальные замечания ниже описывают состояние до внесённых владельцем базы данных обновлений.

## Текущее состояние интеграции после обновления базы

- API получает 20 записей. Финансирование, уровень и направление заполнены во всех 20; язык заполнен в 17; дедлайн передан для 5 конкретных наборов. У общих страниц без единого срока дедлайн остаётся пустым.
- Для всех 20 записей API возвращает требования, документы и официальный источник. На странице рядом с каждым подтверждённым пунктом показывается ссылка на источник.
- Три общие страницы не содержат языка: `erasmus-mundus::general`, `ferienjob::general`, `germany-internships::general`. Интерфейс показывает «Не указано», пока значение не появится в базе.
- Все записи пока имеют статус `needs_review`, поэтому бейдж страницы остаётся «Требует проверки». Этот статус не скрывает пункты требований/документов, если их собственный статус `verified` или `approved`.
- Просмотр страницы после изменения базы загружает актуальные значения; уже открытая страница требует обновления.

## Почему на странице показано «Не указано»

В исходной проверке перед обновлением все 15 строк имели пустые основные поля. После обновления владельцем базы показатели приведены выше. Важно различать вложенные подтверждённые элементы в `payload_json` и отдельную таблицу `dbo.field_evidence`: текущий API читает подтверждённые элементы именно из JSON.

Текущий API читает основные поля из `dbo.opportunities.payload_json`, срок из `dbo.opportunities.deadline`, а требования и документы — из `payload_json.fields.requirements` / `payload_json.fields.documents` только при статусе элемента `verified` или `approved`. Изменение одной лишь таблицы `dbo.field_evidence` экран не обновит.

| Поле на экране | Текущее место хранения | Что требуется |
|---|---|---|
| Финансирование | `payload_json.financing` | Проверенное описание условий конкретного набора или явная пометка, что условия зависят от вакансии |
| Дедлайн | `opportunities.deadline` | Дата ISO `YYYY-MM-DD` только для конкретного набора; для общей страницы оставить `NULL` |
| Уровень | `payload_json.education_level` | Например, «Профессиональное обучение» для Ausbildung |
| Направление | `payload_json.field_of_study` | Специальность конкретной вакансии; у общей страницы — «Разные профессии» |
| Язык | `payload_json.language` | Язык обучения; отдельное требование к владению языком — `minimum_language_level` |
| Требования | `payload_json.fields.requirements[]` | Чётко сформулированные пункты с `text`, `source_url`, `status` и датой сверки |
| Необходимые документы | `payload_json.fields.documents[]` | Реальные документы и этап подачи; не путать ссылки на инструкции с самими документами |

## Предложение для `ausbildung::general`

Эта строка описывает направление Ausbildung в целом, а не открытую вакансию работодателя. По отчёту и [Федеральному агентству по труду Германии](https://www.arbeitsagentur.de/arbeiten-in-deutschland/ausbildung-in-deutschland):

- `education_level`: «Профессиональное обучение».
- `field_of_study`: «Разные профессии; зависит от места обучения».
- `language`: «Немецкий».
- `minimum_language_level`: «Обычно B1 для визы; требования работодателя уточняются отдельно». Агентство указывает B1 как обычное требование для визы, а не универсальный порог каждой вакансии.
- `financing`: «Зависит от типа обучения и работодателя; для визы необходимо подтвердить обеспечение проживания». [Официальное разъяснение Make it in Germany](https://www.make-it-in-germany.com/en/study-vocational-training/training-in-germany/vocational) различает оплачиваемую дуальную и школьную формы обучения.
- `deadline`: оставить `NULL`. Для этой общей страницы нет одного срока подачи. Срок указывать в отдельной записи конкретной вакансии или набора.
- Требования: место профессионального обучения; немецкий язык; признание школьного аттестата для профессиональной школы; подтверждение достаточных средств для визы. Разделить требования к поступлению, школе и визе в следующей версии модели данных.
- Документы из отчёта: подтверждение места обучения (для визы), подтверждение средств (для визы), подтверждение признания школьного аттестата (для профессиональной школы). Это **не полный список документов для заявки работодателю**; его следует брать из конкретной вакансии.

Текст отчёта `JolTap_online.docx` подготовлен автоматически и сам предупреждает, что общая страница не подтверждает открытый набор. Поэтому его фрагменты нельзя массово переводить из `candidate` в `verified`. Перед публикацией каждого пункта нужно открыть официальную страницу, проверить формулировку и дату, затем сохранить источник и статус сверки.

## Порядок внесения

1. Для каждой из 20 строк определить тип: общая страница программы, конкретный набор или конкретная вакансия. Дедлайн и точное финансирование вносить только для конкретных наборов.
2. Для подтверждённых полей сохранить значение, URL официального источника, дату проверки и редактора. Для неизвестных оставить `NULL` и показывать причину на экране.
3. Требования и документы перенести в структурированный формат с отдельным статусом для каждого пункта. В текущем API это массивы внутри `payload_json`; в будущем стоит читать нормализованные записи из `field_evidence` либо отдельной таблицы, чтобы исключить дублирование.
4. Проверить изменения на одной записи (`ausbildung::general`), затем на остальных программах. Не присваивать общей странице статус «открыт набор» без конкретного объявления.

Изменения в рабочей базе требуют отдельного поручения согласно `spec.md`; данный план не выполняет SQL-запись.
