# BilimJol — спецификация проекта

## Цель

Создать русскоязычный адаптивный веб-прототип BilimJol — единого каталога образовательных возможностей для школьников и студентов Кыргызстана. Каталог помогает находить проверенные программы, понимать требования и не пропускать сроки подачи.

## Решения заказчика

- Интерфейс первой версии — на русском языке.
- Визуальная основа — логотип BilimJol и присланный мобильный экран выбора образовательного пути: насыщенная сине-фиолетовая шапка, светлые поверхности карточек, цветовые акценты и mobile-first адаптация.
- Начальный демонстрационный срез: адаптивный каталог возможностей с поиском и фильтрами, карточки и подробная страница программы, демонстрационные данные.
- Развивать приложение итеративно, фиксируя состояние и проверяя каждую функцию тестами до реализации.
- Источник существующих данных — SQL Server 2022, база JolTap. Схема живой базы сверена со snapshot; API читает таблицы `dbo.opportunities`, `dbo.opportunity_categories`, `dbo.opportunity_countries`. Не менять и не перезаписывать базу JolTap ради веб-приложения.
- Подключение использует переменную окружения `ConnectionStrings__JolTap` и Windows Integrated Security. Если переменная не задана, можно включить демонстрационный источник.
- Логотип и референс дизайна находятся в `assets/`.

## Технологическая основа

- Frontend: React, TypeScript, Vite, Tailwind CSS, React Router, Axios.
- Backend: C#, ASP.NET Core Web API, Entity Framework Core, ASP.NET Core Identity, JWT, Swagger.
- Данные: существующий SQL Server 2022 JolTap. Не заменять PostgreSQL или SQLite без явного пересмотра требований заказчиком.
- Git; frontend и backend — отдельные приложения.
- Секреты и строки подключения — только в переменных окружения или локальной конфигурации, исключённой из Git.

## Предлагаемый порядок работ

1. Зафиксировать архитектуру, структуру папок и критерии готовности.
2. Изучить SQL snapshot JolTap, добавить EF Core entities и mapping возможностей и поступления. Перед подключением сверить схему и доступ к живой базе.
3. Реализовать API каталога с поиском, фильтрами и деталями на демонстрационном источнике.
4. Реализовать React-каталог и страницу программы, подключённые к API.
5. [Завершено] Добавить избранное, отслеживание дедлайнов и checklist документов на локальном демо-профиле.
6. [Завершено] Опубликовать frontend на GitHub Pages с тестами в CI и fallback-маршрутизацией. Публичная версия использует только явно демонстрационные данные; API и JolTap не публикуются.
7. [Завершено] Добавить локальную демо-регистрацию и вход по email/паролю с профилем в браузере. Это прототип без серверной аутентификации: не хранить пароль в открытом виде, не обещать синхронизацию между устройствами. Админ-панель отложена; JolTap остаётся read-only.
8. Для production перенести аккаунты и профили на серверное защищённое хранилище, добавить роли и только затем реализовывать админ-панель управления и верификации программ.
9. После стабильного базового MVP спроектировать AI-помощника, который отвечает только по профилю и подтверждённым требованиям программы; неизвестные сведения обозначать как недостаток данных.

Порядок этапов можно продолжать по указанию заказчика. Подключение JolTap выполнено read-only; пользовательские данные и авторизация требуют отдельного этапа.

## Критерии, которые нельзя менять без явного решения заказчика

1. Продукт называется BilimJol и предназначен для образовательных возможностей, релевантных школьникам и студентам Кыргызстана.
2. Первый интерфейс — русский; адаптивная вёрстка начинается с мобильного экрана и опирается на предоставленные логотип и референс.
3. Frontend и backend — отдельные приложения на согласованном стеке React/TypeScript и ASP.NET Core/C#.
4. Использовать SQL Server 2022 JolTap как источник имеющихся данных. Не пересоздавать, не очищать и не менять существующую БД без отдельного явного поручения.
5. Не выдумывать требования программ, дедлайны, финансирование, документы и подтверждённость. Недостающие данные явно показывать как неизвестные.
6. Пароли не хранить открытым текстом. Секреты и credentials не включать в исходники.
7. Код организовывать по компонентам и слоям, с валидацией и обработкой ошибок; не собирать приложение в один файл.
8. AI не входит в начальный базовый MVP и добавляется только после него. Он не утверждает соответствие условиям без подтверждения источниками.
9. Перед реализацией каждой функции сначала добавить тесты, затем реализовать и запускать проверки после изменений до зелёного результата.
10. Каждый этап имеет критерий готовности; фиксировать его результат, затронутые файлы и команды проверок.

## Текущий статус

- Основа проекта, русскоязычная спецификация, логотип и референс интерфейса подготовлены.
- Backend API .NET 10 предоставляет список и подробности возможностей. При наличии `ConnectionStrings__JolTap` используется read-only EF Core источник JolTap; без неё работает in-memory демонстрационный источник.
- Реализованы поиск и фильтры по стране, категории, уровню образования, направлению, финансированию, языку и сроку подачи. Каждая демонстрационная возможность содержит `isDemo=true` и `isVerified=false`; ссылки ведут на `example.org`. Записи JolTap помечены статусом проверки.
- React-приложение подключено к API, содержит каталог, фильтры, карточки и страницу подробностей; адаптировано для мобильного и широкого экранов. Интерфейс русский и использует присланные логотип и визуальный референс.
- Избранное, отслеживание дедлайнов и отметки чек-листа сохраняются в `localStorage` этого браузера; вход, серверная синхронизация и уведомления пока не реализованы.
- Перед реализацией добавлены тесты правил фильтрации API, фильтрации frontend, browser-state, передачи источников доказательств, static hosting и демо-аутентификации: 17 backend-тестов и 23 frontend-теста проходят; production-сборка frontend успешна.
- SQL Server 2022/JolTap подключён read-only к локальному SQL Server. API возвращает 20 возможностей; база не меняется приложением.
- Живая схема выявила другие размеры строк, чем snapshot: mapping исправлен и закреплён тестами.
- Записи со статусом `needs_review` помечаются как «Требует проверки»; требования и документы выводятся только со статусом `verified`/`approved`, вместе с источником и разделом страницы. Пустые языки и дедлайны не выдумываются.
- Frontend опубликован по адресу https://sagakri.github.io/bilim-jol/. GitHub Actions проверяет frontend и автоматически публикует его на push в `main`; статическая версия содержит две демонстрационные записи и не подключается к локальной БД/API.
- Согласовано для следующего этапа: демо-регистрация по email/паролю с профилем только в браузере; серверная аутентификация и админ-панель сейчас не входят.
- Демо-аккаунт реализован: регистрация, вход, выход и редактирование имени профиля; email нормализуется, пароль хэшируется PBKDF2 и не возвращается в публичную модель профиля. Формы и профиль доступны на `/register`, `/login` и `/profile`; интерфейс сообщает об ограничениях браузерного хранения.

## Критерии этапа «Демо-аккаунт»

- Пользователь может зарегистрироваться по email, имени и паролю, войти, выйти и открыть свой профиль.
- Email приводится к единому регистру; повторная регистрация на тот же email отклоняется.
- Пароль никогда не сохраняется в открытом виде; браузерная регистрация обозначена как демо и не выдаётся за защищённый серверный аккаунт.
- Учётные записи существуют только в localStorage этого браузера и не синхронизируются между устройствами.
- Отсутствуют роли и публичное назначение администратора.
- Перед реализацией сначала добавляются тесты валидации, регистрации, проверки пароля, сессии и восстановления повреждённого локального хранилища.

## Критерий готовности текущего прототипа

- Локально запускаются API и frontend согласно README.
- Пользователь может искать программы, сочетать фильтры, открыть подробности и увидеть требования, документы, сроки/поля только там, где они заданы.
- Пользователь может локально сохранить программу, отслеживать дедлайн и отмечать подготовленные документы.
- Демонстрационные и непроверенные данные явно обозначены.
- Backend-тесты, frontend-тесты и frontend production build проходят успешно.
